# AGENTS.md

Instructions for AI coding agents working in this repository. `CLAUDE.md` imports this file.

## Project

Magpie: single-user, self-hosted archive for content from any site (Instagram first; TikTok, YouTube, Pinterest, X, Reddit, generic web). Clients share a URL → API stores an item → worker downloads media, makes thumbnails, extracts keywords, suggests folders/tags. Read [docs/architecture.md](docs/architecture.md) before non-trivial changes.

## Hard rules

- **TypeScript only** for project code. No Python modules. `yt-dlp` / `gallery-dl` are external CLIs invoked via subprocess with JSON output — never import them as libraries or add Python source.
- **Strict typing.** `strict: true`, no `any`, no `@ts-ignore`. Use `unknown` + zod at boundaries (HTTP input, subprocess output, env vars, JSON columns).
- **The API contract lives in `packages/shared`.** Request/response zod schemas are defined once there and used by both `apps/api` and `apps/mobile`. Never duplicate types across packages.
- **DB schema changes go through Drizzle migrations** (`pnpm db:generate`). Never edit an applied migration; add a new one.
- **Storage access goes through `BlobStore`** (`packages/storage`). No direct `fs` or S3 calls for media anywhere else.
- **Source-agnostic core.** No site-specific logic outside `packages/shared/src/sources/<id>.ts` and `apps/worker/src/sources/<id>.ts`. `items.source` is text validated against the registry — never a Postgres enum. See [docs/sources.md](docs/sources.md).
- **SSRF guard on every outbound fetch.** Any user-supplied URL (and each redirect hop) goes through the guard in `apps/worker/src/net/` before any request. See [docs/security.md](docs/security.md).
- **Expo CNG — never commit native projects.** `apps/mobile/android/` and `apps/mobile/ios/` are generated by `expo prebuild` and gitignored. All native configuration (permissions, intent filters, manifest entries, plugins) goes in `apps/mobile/app.config.ts` via config plugins; if no plugin exists, write a local one in `apps/mobile/plugins/`. Never hand-edit generated native files.
- **Expo Router for all navigation** (file-based routes in `apps/mobile/app/`). No React Navigation setup outside what Expo Router provides.
- **NativeWind is mandatory for styling** in `apps/mobile`. Use Tailwind classes via `className`; no `StyleSheet.create`, inline style objects, or other styling libraries (styled-components, Tamagui, etc.). Exceptions only where a third-party component cannot take `className` — wrap it with `cssInterop`/`remapProps` instead.
- **Env via t3-env only.** Each app has `src/env.ts` using `createEnv` from `@t3-oss/env-core`; read config only through the exported `env` object, never `process.env` directly. Expo client vars use the `EXPO_PUBLIC_` prefix and never hold secrets.
- **Never commit secrets.** Tokens, cookies, DB URLs live in env vars / mounted files. `.env` is gitignored; update `.env.example` when adding a variable.
- **Single-tenant by design.** No `user_id` columns; auth is one static bearer token (see [docs/security.md](docs/security.md)). Do not add multi-user plumbing unless asked.
- **ARM64 target.** Docker images must build for `linux/arm64` (Raspberry Pi 5). Avoid native deps without ARM64 prebuilds.

## Conventions

- Package manager: **pnpm** workspaces + turborepo. Node 24 (`.nvmrc`).
- ESM everywhere (`"type": "module"`).
- IDs: UUIDv7 (time-sortable), generated in app code.
- Timestamps: `timestamptz`, stored UTC.
- Env vars parsed once at startup with t3-env (`src/env.ts` per app); fail fast on invalid config.
- Mobile UI: React Native Reusables components (shadcn/ui for RN) in `apps/mobile/components/ui/`, styled with NativeWind classes. Add components with the RNR CLI; don't hand-roll primitives that RNR provides. Theme tokens are CSS variables in `global.css`.
- Mobile state: **server data → TanStack Query** (never copied into a store); **local UI state/preferences → Zustand** stores in `apps/mobile/stores/`, persisted with `persist` + MMKV; **API token → `expo-secure-store`** only.
- Errors: API returns `{ error: { code, message } }` with proper HTTP status. Worker jobs throw; pg-boss handles retry.
- Logging: structured JSON (pino). Never log tokens, cookies, or signed URLs.
- Naming: files `kebab-case.ts`, types `PascalCase`, DB tables/columns `snake_case`, TS fields `camelCase` (Drizzle maps).
- Keep comments sparse; explain *why*, not *what*.

## Branches and releases

- **`main` is the release branch.** Never commit to it directly; it only moves when the owner says to "release".
- **All development happens on `dev`.** Branch from and commit to `dev` (short-lived feature branches off `dev` are fine, merge back into `dev`).
- **Versioning: SemVer `<major>.<minor>.<patch>`**, single source of truth is the `version` field in `apps/mobile/app.config.ts`. It is edited by hand; no bump scripts or CI auto-versioning. Anything else that needs the version (Android `versionCode`, API `/health`) derives it from that value — e.g. `versionCode = major * 10000 + minor * 100 + patch`.
- **Changelog: `CHANGELOG.md`** (Keep a Changelog) is the only source of release notes and of the in-app "What's new". Every user-visible change on `dev` adds a bullet under `## [Unreleased]` in the same change, written for app users (not commit-style). Commits are not parsed; the owner's commit messages may not be conventional.
- **Release procedure** (only on the owner's explicit "release"; full steps in [docs/releases.md](docs/releases.md)):
  1. On `dev`, confirm the bump with the owner (patch / minor / major) and update `version` in `app.config.ts`.
  2. Fill gaps in `[Unreleased]` from `git log <last tag>..dev`, then `node scripts/changelog.ts release X.Y.Z`; show the owner the entry.
  3. `pnpm typecheck && pnpm lint && pnpm test` pass; commit `chore(release): vX.Y.Z`.
  4. Merge `dev` into `main` (`--no-ff`), tag `vX.Y.Z` on `main`, push `main`, `dev` and the tag. CI (`.github/workflows/release.yml`) builds the APK and images and publishes the GitHub release.

## Commands

```sh
pnpm dev            # all apps in watch mode
pnpm build          # build all
pnpm typecheck      # tsc --noEmit across workspace
pnpm lint           # eslint
pnpm test           # vitest
pnpm db:generate    # drizzle-kit generate migration from schema
pnpm db:migrate     # apply migrations to DATABASE_URL

# mobile (apps/mobile)
pnpm --filter @magpie/mobile start            # Metro + dev client
pnpm --filter @magpie/mobile android          # expo run:android (prebuild + install dev build)
pnpm --filter @magpie/mobile prebuild:clean   # expo prebuild --clean (regenerate native dirs)
```

Before finishing a change: `pnpm typecheck && pnpm lint && pnpm test` must pass.

## Where things go

| Change | Location |
|---|---|
| New endpoint | schema in `packages/shared/src/api/`, route in `apps/api/src/routes/` |
| New table/column | `packages/db/src/schema/`, then `pnpm db:generate` |
| New background step | `apps/worker/src/jobs/`, register in `apps/worker/src/index.ts`, document in `docs/worker-pipeline.md` |
| New source (site) | `packages/shared/src/sources/<id>.ts` (`SourceDef`) + `apps/worker/src/sources/<id>.ts` (`SourceFetcher`), register both indexes, follow the checklist in `docs/sources.md` |
| New fetch engine | `apps/worker/src/strategies/<id>.ts` returning `FetchResult` |
| New UI component | `npx @react-native-reusables/cli add <name>` → `apps/mobile/components/ui/` |
| New client-side store | `apps/mobile/stores/<name>.ts` (Zustand) |
| New env var | the app's `src/env.ts` + `.env.example` + `docs/deployment.md` |
| New storage backend | `packages/storage/src/drivers/` implementing `BlobStore` |
| User-visible change | bullet under `## [Unreleased]` in `CHANGELOG.md` |
| Release / CI build change | `.github/workflows/release.yml` + `docs/releases.md` |
